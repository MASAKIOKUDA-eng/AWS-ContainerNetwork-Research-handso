## 撮っておくスクリーンショット（登壇のバックアップ）

- [ ] CloudFormation：5 つのスタック（`CREATE_COMPLETE`）
- [ ] VPC コンソール：IPv6 の CIDR が付いたサブネット（エッジはデュアルスタック / ワークロード）
- [ ] エンドポイントサービス：`Acceptance required`、サポートする IP アドレスタイプが IPv4 + IPv6、承諾待ちの接続
- [ ] Lattice：利用側 VPC の関連付けと SG が付いたサービスネットワーク
- [ ] Lattice のアクセスログ：`authDeniedReason` のある行と `callerPrincipal` のある行
- [ ] trusted / untrusted / iam-required のプローブ出力
- [ ] 提供側のアクセスログ：PrivateLink と Lattice の `remote`（source-ip-report）
- [ ] k6 の 1 回分のサマリー（方法を示すため）
- [ ] IPv6 の `pkt-srcaddr` がわかる Flow Logs のクエリ結果

## コストのメモ（始める前に最新の料金を確認）

起動中に時間でかかる主なもの：インターフェイスエンドポイント（エンドポイント × AZ：2 VPC × 2 AZ × 4〜7 個）、NLB、VPC Lattice のサービス、Fargate タスク 4 つ、負荷生成 EC2。インターフェイスエンドポイントと Lattice はデータ処理量（GB）にも課金されます。計測は 1 回で済ませ、その日のうちにすべて削除します。

## 当日のセキュリティ上の注意

- アカウント ID、VPC ID、ARN、プリンシパルを含むアクセスログの行をマスクせずにスライドに載せない
- 普段使いのアカウントの AWS コンソールを映さない。検証用アカウントを使う
- 公開エンドポイントに対するライブデモはしない（設計上そもそも存在しない）
